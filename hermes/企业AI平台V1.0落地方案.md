## 1 项目概述

### 1.1 项目背景

1. 企业AI平台为星纪年自研的企业级 AI 智能体平台（原"云枢"，2026-08-07 更名），以 Hermes 为核心调度引擎，以飞书/钉钉为生态底座，面向企业提供"数据整合 + AI 决策 + 结果呈现"的一体化能力。
2. 平台定位为可复制的标准化产品：以统一的底层框架，按企业场景装载不同功能（类"麦当劳/肯德基"模式——架构一致，仅装载内容不同）。
3. V0.5 版本（2026-08-10 对齐）已完成：驾驶舱 UI 定版、前后端解耦、接口对齐约 2/3、Hermes 接入（问答与执行）、知识库接入。

### 1.2 项目目标

在 V0.5 基础上完成 V1.0 增量，实现\*\*"AI 执行任务 → 结果可视化 → 人工审阅决策"\*\*的核心闭环，达成：

1. 单人版可登录、可试用、可演示；
2. 平台形成差异化亮点（区别于普通办公系统）；
3. 为后续版本（多人协同、记忆/技能打通、客户交付）奠定核心能力基础。

## 2 功能范围与验收标准

### 2.1 版本关系

| 版本 | 定位 | 状态 |
|-|-|-|
| V0.5 | 单人版基础框架（驾驶舱 UI、解耦、Hermes 接入、知识库接入） | 开发中 |
| V1.0 | 在 V0.5 上实现"任务执行 → 结果可视化 → 人工审阅决策"闭环 | 本阶段目标 |

### 2.2 V1.0 功能范围（5 项增量）

**功能一：智能决策框（核心）**

- 驾驶舱核心区域，横向拉通至整行
- 列表展示 AI 自动执行任务的结果（pending 决策）
- 每条：任务名称、生成时间、状态标识；点击查看详情（Markdown 渲染）
- 提供"同意""驳回"操作入口
- 仅展示定时/条件任务结果，单次对话不进框（避免噪音）

**功能二：定时任务查看页面**

- 独立页面集中展示已创建定时任务
- 每任务：名称、触发时间/条件、执行状态、最近执行时间
- 支持查看详情与编辑
- 入口：驾驶舱"常用功能"按钮

**功能三：接口预留（AI 对话创建任务）**

- 预留任务创建接口，支持 AI 通过自然语言对话创建定时/条件任务
- 用户表达需求 → AI 识别意图 → 调接口创建 → 任务进入调度列表
- 任务执行结果自动投递至智能决策框

**功能四：同意/驳回与结果沉淀**

- 同意：确认闭环，结果写入经验库/Memory（沉淀可复用经验）
- 驳回：填写驳回理由（必填）→ 理由写回知识库（AI 自我修正依据）
- 驳回后：归档或触发重新生成（反馈循环回到生成 pending 决策）
- 本版本仅单次交互闭环，不做多轮二次交互

**功能五：接口对齐收尾**

- 前后端接口对齐从 2/3 推进至 100%
- 保障前端各页面数据链路完整（驾驶舱、AI 服务、待办、重要文档等既有模块）
- 接口文档同步更新为开发基线

## 3 技术方案

### 3.1 总体架构

```Plaintext
┌─────────────────────────────────────────────┐
│ 前端（驾驶舱 / 智能决策框 / 定时任务页面）        │
├─────────────────────────────────────────────┤
│ 接口层（任务 CRUD / 决策列表 / 审阅 / 详情）      │
├─────────────────────────────────────────────┤
│ 后端（任务持久化 / 调度器 / Worker / 状态机）     │
├─────────────────────────────────────────────┤
│ AI 服务（Hermes 调度 / 意图识别 / 结果生成）      │
├─────────────────────────────────────────────┤
│ 数据层（业务数据：飞书/钉钉 API / 知识库 / 经验库）│
└─────────────────────────────────────────────┘
```

### 3.2 任务执行闭环流程

```Plaintext
用户定义自然语言任务
        ↓
任务定义持久化
        ↓
调度器/Worker 到期执行
        ↓
读取业务数据
        ↓
调用 AI 服务
        ↓
生成 pending 决策
        ↓
驾驶舱展示（智能决策框）
   ↓            ↓
  同意          驳回
   ↓            ↓
写入 Memory/经验方法   归档或重新生成 ←────┐
                        （反馈循环：重新生成 → 生成 pending 决策）
```

### 3.3 关键技术点

| # | 技术点 | 说明 |
|-|-|-|
| 1 | 任务持久化 | 数据库存储任务定义（类型、触发条件、执行参数、状态） |
| 2 | 调度器 | 支持 cron 定时与条件触发；失败重试（基础级） |
| 3 | AI 意图识别 | 区分"单次执行"与"定时/条件任务"；创建后返回确认反馈 |
| 4 | 结果投递 | 执行完成生成 pending 决策条目，写入驾驶舱数据源 |
| 5 | 审阅状态机 | pending → approved / rejected；驳回理由必填入库 |
| 6 | 反馈循环 | 驳回可触发重新生成（回到生成 pending 决策） |

### 3.4 接口契约

1. 接口范围：任务 CRUD、决策列表、决策审阅、详情获取
2. 契约确认时间：2026-08-15（开发前）
3. 契约文档作为开发基线，双方按统一契约开发
