# 日程自动归档到周任务交接说明

版本：2026-08-17

适用分支：`codex/frontend-replacement`

本文用于交接给后端负责人，描述“日程由日切到周”的真实业务含义、职责边界、建议接口和验收标准。

## 1. 需求定义

这里的“日切到周”不是前端视图切换，而是任务生命周期迁移：

- 用户当天未完成的日任务，在跨日后自动归档为周任务。
- 已完成任务不参与自动归档。
- 前端只展示最终结果，不在本地伪造迁移成功。

## 2. 职责边界

### 后端负责

- 判断跨日条件。
- 扫描未完成的日任务。
- 将任务自动归档到周任务。
- 保证幂等。
- 记录归档时间、归档原因和审计信息。

### 前端负责

- 读取接口返回的日任务和周任务。
- 展示归档后的结果。
- 如果后端失败，显示真实错误或空态。
- 不在 `state.tasks` 上本地模拟“自动归档成功”。

## 3. 推荐运行逻辑

1. 定时任务按用户时区或组织时区执行。
2. 找出截至当前跨日点仍未完成的日任务。
3. 将这些任务的归属从 `day` 改为 `week`。
4. 保留原始创建时间、截止时间和完成状态历史。
5. 写入归档时间和归档批次。
6. 前端下次拉取列表时直接看到周任务。

## 4. 建议数据字段

建议至少保留：

- `task_scope`: `day | week`
- `original_scope`
- `original_due_at`
- `archived_at`
- `archive_reason`: `overdue`
- `archive_batch_id`
- `week_key`

说明：

- `week_key` 建议用 ISO 周或业务周编号。
- `archive_batch_id` 便于回溯某次定时任务处理结果。

## 5. 建议接口契约

如果后端准备让前端区分日任务和周任务，建议列表接口支持筛选：

| Method | Path | 用途 |
| --- | --- | --- |
| `GET` | `/api/work-items?scope=day` | 获取日任务 |
| `GET` | `/api/work-items?scope=week` | 获取周任务 |
| `PATCH` | `/api/work-items/{id}/status` | 任务状态流转 |

如果后端已经有统一的 work item 列表接口，也可以在响应里直接返回 `task_scope`，由前端按字段分组。

## 6. 幂等与异常

- 同一任务只能归档一次。
- 已归档任务再次执行定时任务时应跳过。
- 完成任务不应被归档。
- 如果任务在临界点被用户手动完成，后端以最终持久化状态为准。
- 归档失败必须可重试，且不能产生重复记录。

## 7. 时区规则

- 归档边界应以用户或组织的明确时区为准。
- 不建议直接使用服务器本地时区。
- 如果组织和用户时区不一致，需要后端定义优先级。

## 8. 前端配合方式

前端现阶段只需要：

- 按接口结果展示日/周任务。
- 在页面刷新后重新读取列表。
- 对归档失败显示真实错误。

前端不会承担自动迁移逻辑，也不会把本地任务状态当成最终结果。

## 9. 验收标准

- 跨日后未完成的日任务会自动进入周任务。
- 已完成任务不会被重复归档。
- 重复执行定时任务不会生成重复周任务。
- 前端刷新后能看到最新列表。
- 失败时返回真实错误，不出现假成功。
