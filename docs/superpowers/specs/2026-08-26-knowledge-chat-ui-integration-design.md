# 知识库对话前端接入设计

## 目标

通过现有后端接口，让当前 React 对话页面真正支持基于知识库的问答。用户可以在普通对话和知识问答之间切换、选择授权范围内的知识资料、发送问题，并查看每条回答引用的知识来源。

## 现有能力边界

后端已经具备本次修复需要的能力：

- `POST /api/chat/sessions`：创建 `agent` 普通会话或 `knowledge` 知识会话。
- `PUT /api/chat/sessions/{session_id}/knowledge-scope`：保存 `all_visible`、`selected` 或 `none` 知识范围。
- `POST /api/chat/sessions/{session_id}/messages`：在知识会话中检索授权知识，并在回答事件前发送 `knowledge.context` 事件。
- `GET /api/knowledge/citations/{turn_id}/{ordinal}`：按照当前权限重新校验并解析历史引用。
- `GET /api/knowledge/{entry_id}/content`：引用通过权限校验后，读取当前可访问的知识内容预览。

本次修复只接通 React 前端，不修改检索排序、知识入库、权限模型、数据库结构或后端接口格式。

## 用户体验

`/chat` 页面增加“普通对话”和“知识问答”两种模式。两种模式分别管理会话列表和缓存，防止普通会话与知识会话混用。

在知识问答模式中：

- 新会话使用 `surface: "knowledge"` 创建。
- 新建知识会话后，通过服务端知识范围接口将范围初始化为 `all_visible`。
- 页面提供“全部可见知识”和“指定知识”两种范围。
- 选择“指定知识”后，页面以复选框展示当前用户可访问且有效的知识条目。
- 指定知识最多选择 50 条，与现有后端限制保持一致。
- 用户明确点击应用后才保存知识范围。范围未配置、指定范围为空或正在保存时，不能发送问题。
- 回答包含引用时，在回答下方显示“知识来源”。
- 用户点击引用时，前端先按当前权限解析引用，再读取知识内容预览。权限失效时只显示不可用提示，不展示历史缓存内容。

`/knowledge` 页面增加“进入知识问答”入口，跳转到 `/chat?surface=knowledge`。普通对话继续使用 `surface: "agent"`，且不携带知识来源 ID。

## 组件调整

### ChatPage

`ChatPage` 在现有 `ChatService` 和 `ChatStreamService` 之外，接收现有的 `KnowledgeService`，负责管理：

- 当前选择的会话模式；
- 按模式隔离的会话和当前会话；
- 当前用户可访问的知识条目；
- 正在编辑和服务端已确认的知识范围；
- 引用解析及内容预览状态。

会话数据映射保留后端返回的 `surface`、`knowledge_scope` 和 `source_ids`。历史消息映射保留 `turn_id`、知识引用、检索模式和被拒绝来源数量。收到 `knowledge.context` 流式事件后，将同样的信息写入当前生成中的 AI 消息。

### App

`App` 将运行时已有的知识库服务传给 `ChatPage`。访问 `/chat?surface=knowledge` 时默认进入知识问答，否则默认进入普通对话。

### KnowledgePage

`KnowledgePage` 只增加“进入知识问答”入口，现有知识条目创建、上传和归档行为保持不变。

## 数据流程

1. 用户进入知识问答。
2. 页面按 `surface=knowledge` 加载知识会话，同时加载当前可访问的知识条目。
3. 用户新建会话时，前端创建 `knowledge` 会话并将知识范围保存为 `all_visible`。
4. 用户修改知识范围时调用 `setKnowledgeScope`；只有服务端保存成功后才更新本地已确认状态。
5. 用户发送问题时继续使用现有 SSE 消息接口，不在消息中发送旧版 `source_ids`。
6. 后端根据会话持有的知识范围检索授权内容，并依次发送 `knowledge.context` 和回答事件。
7. 页面展示回答和引用标题。
8. 用户打开引用时，页面先按会话轮次和引用序号重新校验权限，再请求当前知识内容预览。

## 异常处理

- 会话加载、知识列表加载和范围保存失败时，页面显示明确错误信息。
- 知识范围保存失败时，恢复为上一次服务端确认的范围。
- 知识范围为 `none` 或指定范围为空时，禁止发送知识问题。
- 引用解析或内容预览失败时，显示来源不可用，不复用之前打开过的内容。
- 切换普通对话与知识问答时，先停止正在进行的流式回答，再加载另一种会话。
- 普通对话和联网来源展示行为保持不变。

## 测试范围

前端测试需要证明：

- 普通对话仍然只加载和创建 `agent` 会话；
- 知识问答只加载和创建 `knowledge` 会话，并将新会话初始化为 `all_visible`；
- 指定知识条目通过 `setKnowledgeScope` 保存；
- 知识范围不可用时，输入框不能发送问题；
- 流式回答和历史回答都能显示知识引用；
- 点击引用时，先进行权限解析，再读取内容预览；
- 知识库页面提供知识问答入口；
- 两种会话的缓存互不混用。

验证范围包括定向 React 测试、完整前端测试、代码检查和生产构建。本次不计划修改后端；只有实现过程中发现后端契约缺陷时，才需要补充并运行后端测试。

## 验收标准

- 用户可以从知识库页面或对话模式控制进入知识问答。
- 知识问答发送的问题必须属于后端 `knowledge` 会话。
- 用户可以查询全部可见知识，也可以指定一组有权限的知识条目。
- 回答返回的知识引用清晰可见，并能按照当前权限打开查看。
- 普通对话继续使用 `agent` 会话，原有行为不受影响。
- 定向测试、完整前端测试、代码检查和生产构建全部通过。
