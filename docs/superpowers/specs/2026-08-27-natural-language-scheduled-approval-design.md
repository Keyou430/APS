# 自然对话定时任务与智能决策审批设计

**日期：** 2026-08-27

## 目标

让用户可以通过自然对话生成定时任务草稿，确认后创建任务；每次任务执行结果进入智能决策，按任务配置交给指定审批人同意或驳回。驳回必须填写理由，同意意见可选。审批结果归档并写入组织可检索记忆，不自动执行外部业务动作。

## 已确认规则

1. 聊天只生成任务草稿，不直接创建；用户确认后才创建。
2. 确认页展示任务内容、频率、时区、输出格式和审批规则。
3. 每次执行默认需要审批；创建任务时可关闭审批。
4. 默认审批人为任务创建者；可指定组织成员或角色。
5. 驳回理由必填；同意意见可选。
6. 待审批主动通知平台通知中心，并通过已配置的飞书渠道通知。
7. 审批超时保持 `pending`，不自动同意或驳回；支持提醒和升级审批人。
8. 同意后记录意见、归档结果并写入组织记忆；不执行外部业务动作。

## 架构

PipelineTask 持有审批策略快照，DashboardDecision 持有一次执行结果的审批状态和审批审计字段。聊天平台动作只返回草稿事件，确认动作通过已有 Pipeline 创建接口完成。执行 worker 在产物落库后创建决策，并在同一事务中写入平台通知 outbox；独立的审批提醒 worker 扫描 pending 决策，按提醒与升级时间写入通知 outbox。

审批权限由“能访问组织决策”与“决策是否分配给当前用户”共同决定。角色审批使用任务创建时的角色名称快照，成员审批使用组织成员用户 ID。结果通知只发送轻量状态和平台入口，不携带模型输出全文。

## 数据流

1. 用户在聊天中发送“创建定时任务……”。
2. 后端解析为 `PipelineDraftResponse`，SSE 返回 `platform.action` 草稿事件；不写入 `pipeline_tasks`。
3. 用户在 Pipeline 页面调整审批开关、审批人类型、审批成员/角色、提醒配置并确认。
4. 后端创建 `PipelineTask`，计算下一次运行时间，保存审批策略。
5. scheduler 创建 `PipelineRun`，worker 执行并保存 `PipelineOutput`。
6. 若任务启用审批，worker 创建 `DashboardDecision(status=pending)`，并写入平台通知 outbox 及可路由的飞书 delivery outbox；若关闭审批，则保存结果但不创建待审批项。
7. 审批人提交同意意见或驳回理由。服务端校验分配关系、状态和幂等键。
8. 同意写入 decision memory、审计事件和通知；驳回写入理由、审计事件和通知。两者均不调用外部业务动作。
9. reminder worker 对达到提醒时间的 pending 决策通知当前审批人；达到升级时间后通知升级角色或组织管理员，但决策仍保持 pending。

## 自然语言范围

第一版继续使用现有 cron 内核，并扩展常见中文表达：每天/工作日指定时间、每周指定星期和指定时间、每月指定日期和时间。无法无歧义解析时返回草稿但要求用户在确认页补齐频率，不创建任务。解析逻辑独立于聊天路由，后续可替换为更完整的时间解析器。

## 错误与安全

- 未确认的草稿不能产生任务记录。
- 驳回请求缺少理由返回 422。
- 非当前审批人不能处理决策，返回 403。
- 非 pending 决策不能再次处理，返回 409。
- 同一幂等键和不同 payload 返回 409；相同 payload 重放原结果。
- 审批策略只允许当前组织内有效成员或存在的角色。
- 通知 payload 只包含任务/决策 ID、状态和入口信息，不包含敏感输出内容。
- 提醒 worker 使用幂等 event key，允许重复扫描而不会重复通知。

## 测试验收

- 聊天创建意图只产生草稿事件，不创建 `PipelineTask`；确认创建后才落库。
- 草稿支持确认页所需审批字段和常见频率。
- 执行启用审批的任务创建 pending decision，关闭审批的任务不创建 decision。
- 指定成员和角色的审批授权正确；无关成员不能审批。
- 同意可带意见，驳回必须带理由，均保存审批人和时间。
- 同意创建组织 decision memory；驳回不创建 memory。
- 创建 pending decision 时产生平台和飞书通知 outbox。
- reminder worker 在提醒/升级窗口产生一次性通知，超时不改变决策状态。
- 前端能配置草稿审批规则、输入同意意见、输入驳回理由并展示审批状态。
- 现有 pipeline、聊天、通知、幂等和迁移测试保持通过。
