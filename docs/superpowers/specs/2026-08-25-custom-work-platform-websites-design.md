# 工作平台自定义网站设计规格

日期：2026-08-25

状态：需求已确认，待用户审阅本文后进入实施计划

## 1. 目标与边界

在现有“工作平台”的飞书、钉钉子菜单后，允许当前登录用户维护多个自定义网站。每个网站由用户填写名称和网址，并在统一工作台内尝试 iframe 预览。

本功能只保存当前用户的本地配置，不配置后端接口、数据库迁移、组织共享、权限管理或外部网站授权。飞书和钉钉继续按现有逻辑工作，不被重构为自定义网站。

用户流程固定为：

1. 在“工作平台”子菜单末尾点击“添加自定义网站”。
2. 在新建页填写名称与网址，点击“保存并载入”。
3. 新入口出现在飞书、钉钉之后；点击入口打开对应预览页。
4. 在网站页编辑名称或网址，保存后菜单、页面标题和打开的标签同步更新。
5. 需要移除入口时点击删除并确认；只删除本地配置，不改动外部网站任何数据。

## 2. 已确认的产品决策

| 决策 | 结论 | 原因 |
| --- | --- | --- |
| 保存范围 | 当前用户、本地浏览器 | 与现有嵌入地址一致，避免本次引入服务端治理范围。 |
| 数量 | 支持多个 | 工作平台需要容纳不同业务系统入口。 |
| 菜单入口 | 子菜单末尾固定“添加自定义网站” | 已有网站可一键预览，添加动作不绕行管理页。 |
| 名称 | 用户填写且同一用户下不可重复 | 子菜单和标签页可以明确区分。 |
| 预览失败 | 始终可新窗口打开 | 外部站点可因嵌入安全策略拒绝 iframe，平台不能伪造载入成功。 |
| 编辑删除 | 均支持；删除需二次确认 | 配置可维护，并防止误删入口。 |

## 3. 数据与持久化

### 3.1 本地数据模型

新增 `customWebsitesStorageKey`，用现有 `_saveScoped` / `_loadScoped` 机制按用户保存 JSON 数组。单项结构为：

```js
{
  id: "custom-site-...",
  name: "采购门户",
  url: "https://procurement.example.com/"
}
```

`id` 由前端生成，不接受用户输入，且在用户的列表中唯一。`name` 为去掉首尾空格后的非空文本；比较时忽略英文大小写，禁止与同一列表中的其他名称重复。`url` 为已规范化的绝对 `http:` 或 `https:` 地址。

读取到非数组、缺少必要字段或不合法网址的本地数据时，该条目不进入界面；完全无法解析的当前用户数据回退为空列表。不会读取其他用户的 scoped key，也不调用 `saveEmbedUrlsRemote` 或任何未实现的远端接口。

### 3.2 用户隔离

新存储键纳入现有登录切换、登出和内存重置路径。身份可用后，从当前用户 scoped key 重新载入列表；切换账号时先清空内存中的旧列表，随后只恢复新账号的数据。这样保留各用户自己的本地配置，同时不在 UI 中泄露前一用户的入口。

## 4. 页面和导航结构

### 4.1 工作平台子菜单

“工作平台”固定展示：

1. 飞书
2. 钉钉
3. 所有已保存的自定义网站，按添加顺序排列
4. 添加自定义网站

网站名称以文本形式渲染和转义，不能成为 HTML、选择器或视图 ID 的一部分。每个保存的网站使用前端生成的 `id` 派生稳定的内部视图 ID。

### 4.2 自定义网站页

每个保存的网站有独立的工作区视图和可关闭标签，外观复用飞书、钉钉的页头、地址栏、刷新和“新窗口打开”模式。页面包括：

- 可编辑的名称输入框；
- 可编辑的网址输入框；
- “保存并载入”命令；
- 刷新预览的图标按钮；
- 在新窗口安全打开的图标按钮；
- 删除入口的危险操作按钮。

“添加自定义网站”先打开一个尚未持久化的“新建自定义网站”视图。它不会占用菜单项；只有名称和网址校验通过并保存后，才创建菜单项、预览页和命名标签。删除当前打开的网站时，关闭该网站相关标签和预览视图，并返回飞书入口；删除非当前网站时仅移除其入口和标签。

`validViews` 的静态白名单仍保护固定页面。自定义视图只有在其 `id` 属于当前用户已保存网站时才被接受；保存的活动视图找不到对应网站时回退到飞书，不能因 localStorage 中的任意字符串显示或激活页面。

## 5. 保存、预览与异常处理

### 5.1 输入校验

网址延续现有嵌入体验：未写协议时先补 `https://`，然后通过 `URL` 解析；只有 `http:` 与 `https:` 可以保存。空网址、解析失败、`javascript:`、`file:` 等非网页协议均显示明确错误，不写本地配置。

保存失败时保留用户当前输入和已有 iframe 的上一次有效地址。名称重复、空名称和非法网址都不会覆盖已保存的名称或网址。成功后立即写入当前用户的 scoped localStorage，并更新导航、标签和 iframe。

### 5.2 iframe 限制

外部网站可能使用 `X-Frame-Options` 或 CSP `frame-ancestors` 阻止嵌入。浏览器不能可靠地向宿主页暴露这类跨域失败的细节，因此 UI 不把 iframe 的 `load` 事件解释成“页面已成功可用”，也不显示虚假的成功状态。

预览区域始终提供“新窗口打开”，使用现有 `noopener,noreferrer` 方式打开已保存、已校验的网址。用户可在外部窗口继续访问被拒绝嵌入的网站。

### 5.3 删除

删除按钮先显示 `window.confirm` 二次确认，文案明确“仅移除当前用户的本地入口”。确认后移除该数组项、写回 scoped storage、清理动态 DOM 和对应标签；取消则不改变任何状态。

## 6. 实现边界

实现集中在 legacy 工作台的 `web-platform/src/app.js` 与 `web-platform/index.html`：

- 使用一个可动态填充的自定义网站视图容器和导航渲染函数，避免为每个用户条目在静态 HTML 中预留页面；
- 提取小型纯函数模块，负责记录创建、网址规范化和重复名称校验，UI 代码只处理渲染和用户事件；
- 复用已有嵌入样式与图标，不修改 React-owned 路由、后端 API、数据库或部署配置；
- 只通过转义后的文本和值写入 HTML 属性，iframe 地址仅来自已校验的规范化网址。

不在本次范围内的能力包括：网站排序、分组、导入导出、团队共享、管理员分发、站点连通性探测、绕过 iframe 限制或代理加载外部站点。

## 7. 测试与验证

新增针对纯函数模块的测试，至少覆盖：

1. 规范化有效 HTTPS 和省略协议的网址；
2. 拒绝空网址、无效网址和非 `http/https` 协议；
3. 拒绝空名称及忽略大小写后的重复名称；
4. 编辑当前条目时允许保留自身名称；
5. 不合法的持久化记录不会变成菜单或 iframe 地址。

增加浏览器流程验证：创建两个网站、确认子菜单顺序、分别进入预览、编辑名称与网址、拒绝重复名称、删除确认和刷新后的当前用户恢复。验证期间使用本地可嵌入页面，不把第三方站点的 CSP 表现当成测试前提。
